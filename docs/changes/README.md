# Registro de cambios

Cada modificación funcional, de datos, contrato, seguridad, infraestructura o configuración debe tener un archivo propio: `YYYY-MM-DD-slug.md`. Este índice se ordena de más reciente a más antiguo.

Una entrada debe separar hechos verificados de pendientes, incluir los archivos impactados, compatibilidad, validación y rollback. No documentar cambios ajenos como propios.
